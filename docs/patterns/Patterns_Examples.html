● 초급 Getting Started 폴링 패턴으로 NFC 리더 이상을 감지하고 알림 보내기
G-1 초급 NFC 리더 이상 감지 → 즉시 알림 폴링 루프
교사 A의 교실 NFC 리더가 수업 중 가끔 오프라인이 된다. 오프라인 상태를 1분 안에 감지해 교무실에 Slack 알림을 보내고 싶다. 폴링 패턴을 사용해 리더 상태를 주기적으로 확인하고, 이상 시 즉각 반응하는 루프를 만든다. 전제 조건: classroom-nfc/ 프로젝트 폴더, localhost:3000에서 NFC 서버 실행 중, Slack Webhook URL 환경 변수 설정 완료.
사용 요소
폴링 패턴 /loop
단계별 실행
  1. .claude/loop.md에 폴링 지침 작성

    반복 실행할 점검 내용을 파일로 관리하면 재사용과 팀 공유가 쉬워진다.

    # .claude/loop.md
GET http://localhost:3000/api/reader/status 를 호출한다.
응답의 "status" 필드가 "connected"이면 "✓ NFC 정상"을 출력한다.
"connected"가 아니면 $SLACK_WEBHOOK_URL 로 아래 메시지를 POST한다:
{"text": "⚠️ NFC 리더 오프라인 감지 — 즉시 확인 필요"}
  2. 45초 간격으로 루프 시작

    45초마다 .claude/loop.md 지침을 실행한다. 270초(캐시 유지 상한) 안에서 가장 촘촘한 간격이다.

    /loop 45s
/loop 45s를 실행하면 Claude는 즉시 .claude/loop.md를 읽고 점검을 수행한다. 이후 45초마다 같은 지침을 반복하며, 이상이 감지될 때마다 Slack 알림을 보낸다. 캐시 TTL(300초) 안에서 실행되므로 프롬프트 캐시가 유지되어 비용 효율적이다.
.claude/loop.md를 사용하면 루프 프롬프트를 코드처럼 버전 관리할 수 있다. 팀원이 지침을 수정하면 다음 루프 실행부터 바로 반영된다.
● 중급 Daily Workflow 자기 수정 패턴으로 출석 데이터 품질을 자동으로 높이기
D-1 중급 출석 보고서 품질 자동 개선 — 자기 수정 패턴
교사 B는 NFC 출석 데이터로 생성한 주간 보고서가 형식·내용 기준을 일정하게 충족하지 못한다는 것을 알았다. 생성 → 검증 → 수정을 에이전트가 스스로 반복해 기준을 충족하는 보고서를 만들고 싶다. 전제 조건: generate_report.py(보고서 생성 스크립트)와 check_report.py(품질 기준 검사 스크립트)가 준비되어 있어야 한다.
사용 요소
자기 수정 패턴 /goal
단계별 실행
  1. 초기 보고서 생성

    먼저 원본 보고서를 만든다.

    python generate_report.py --week 2026-W27 --output report.md
  2. 자기 수정 루프 시작

    check_report.py 검사를 통과할 때까지 보고서를 자동으로 개선하도록 /goal을 사용한다.

    /goal python check_report.py report.md 를 실행했을 때 모든 항목이 "PASS"가 되도록 report.md를 수정해줘. 항목별 실패 이유를 분석해 최소한의 수정만 적용하고, 최대 6번 시도 후 남은 실패 항목 목록을 보고해줘
매 턴마다 Claude는 check_report.py 출력을 분석해 어떤 항목이 왜 실패했는지 파악하고, report.md의 해당 부분만 수정한다. 과교정을 피하기 위해 "최소한의 수정"을 명시했다. 모든 항목이 PASS가 되거나 6번 시도를 소진하면 멈춘다.
자기 수정 루프는 report.md를 반복 덮어쓴다. 실행 전에 git add report.md && git stash로 원본을 보존해 두는 것이 좋다.
● 고급 Power User 멀티 에이전트로 전 학교 NFC 데이터를 병렬 처리
P-1 고급 전교 출석 데이터 병렬 검증 파이프라인
행정실 D는 1학년부터 3학년까지 9개 학급의 NFC 출석 데이터를 매일 오후 검증해야 한다. 순차 처리는 너무 오래 걸리므로, 멀티 에이전트 루프로 각 학급 데이터를 병렬로 검증하고 결과를 합산해 교장에게 요약 보고서를 생성하고 싶다. 전제 조건: attendance/ 폴더 안에 학급별 서브폴더(예: grade1-class1/)가 있고 각각 attendance.json이 존재해야 한다.
사용 요소
멀티 에이전트 루프 /goal 자기 수정 패턴
단계별 실행
  1. 병렬 검증 요청

    오케스트레이터 에이전트에게 각 학급을 독립 서브에이전트에 위임하도록 지시한다.

    attendance/ 폴더 안의 모든 학급 서브폴더를 찾아서, 각 폴더의 attendance.json 을 독립적인 서브에이전트로 병렬 검증해줘.
각 서브에이전트는 (1) 중복 기록 제거 (2) 누락 기록 플래그 (3) validate_attendance.sh 통과 세 단계를 수행한다.
모든 서브에이전트가 완료되면 학급별 결과(정상/오류 수/수정 건수)를 표로 집계해서 summary_report.md 에 저장해줘
  2. 요약 보고서 품질 검증

    보고서가 생성되면 자기 수정 루프로 품질을 높인다.

    /goal summary_report.md 가 교장 보고용 형식(학급별 표, 총합 통계, 조치 필요 학급 강조)을 갖추도록 수정해줘. 최대 3번 시도
오케스트레이터 에이전트가 학급 목록을 조회한 뒤, 각 학급에 대해 서브에이전트를 병렬로 실행한다. 서브에이전트들은 독립적으로 파일을 처리하므로 충돌 없이 동시 실행이 가능하다. 모두 완료되면 오케스트레이터가 결과를 집계해 summary_report.md를 작성한다.
각 서브에이전트는 독립 파일만 수정해야 한다. 공유 파일(예: 학교 전체 마스터 DB)을 동시에 쓰면 충돌이 발생한다. 멀티 에이전트는 "읽기 → 독립 처리 → 오케스트레이터 집계" 구조를 유지할 것.
