● 초급 Getting Started Claude Code 세션에서 처음으로 루프를 실행해 보는 첫 단계
G-1 초급 NFC 리더 연결 상태 30초 간격 폴링
교사 A는 학교 복도에 설치된 NFC 리더가 가끔 연결이 끊긴다는 사실을 알았다. 수업 시작 전에 리더가 정상 동작하는지 30초마다 자동으로 확인하고 싶다. Claude Code 루프를 처음 써보는 상황이다. 전제 조건: classroom-nfc/ 프로젝트 폴더에서 Claude Code 세션이 열려 있어야 하며, NFC 서버가 localhost:3000에서 실행 중이어야 한다.
사용 요소
/loop interval 지정
단계별 실행
  1. 프로젝트 폴더로 이동 후 Claude Code 실행

    NFC 학급 관리 프로젝트 폴더에서 Claude Code를 연다. API 엔드포인트 주소를 미리 확인해 둔다.

    cd classroom-nfc
claude
  2. /loop 명령으로 30초 폴링 시작

    인터벌(30s)과 실행할 프롬프트를 함께 입력한다. Claude가 즉시 첫 번째 점검을 실행하고 이후 30초마다 반복한다.

    /loop 30s GET http://localhost:3000/api/reader/status 를 호출해서 NFC 리더 연결 상태를 확인하고, 정상이면 "✓ 정상", 오류면 오류 메시지를 출력해줘
  3. 루프 중단

    점검이 끝나면 Ctrl+C 또는 세션을 닫아 루프를 중단한다.

    Ctrl+C  # 루프 중단
/loop 명령을 받은 Claude는 즉시 프롬프트를 실행한 뒤, ScheduleWakeup 도구로 30초 후 웨이크업을 예약한다. 예약 시간이 되면 같은 프롬프트를 다시 실행하고 결과를 출력한다. 세션이 활성 상태인 한 이 주기가 반복된다.
인터벌을 짧게 할수록 API 호출 횟수가 늘어 비용이 발생한다. 리더 상태 변화 주기에 맞는 간격을 선택하자. 대부분의 경우 60초~120초면 충분하다.
● 중급 Daily Workflow 출석 데이터 검증을 /goal로 자동화하는 실무 워크플로우
D-1 중급 NFC 출석 데이터 무결성 자동 검증
방과 후 출석 데이터를 점검하던 교사 B는 일부 학생의 기록이 중복되거나 누락된 것을 발견했다. 매번 수동으로 확인하기 번거로워, /goal 명령으로 데이터 오류가 0이 될 때까지 자동 수정하도록 설정하고 싶다. 전제 조건: attendance.json 파일이 프로젝트 폴더에 존재하고, 오류 검사 스크립트(validate_attendance.sh)가 준비되어 있어야 한다.
사용 요소
/goal 턴 제한
단계별 실행
  1. 검증 스크립트로 현재 오류 수 확인

    목표를 설정하기 전에 현재 상태를 파악한다.

    bash validate_attendance.sh attendance.json
  2. /goal 명령으로 자동 검증 루프 시작

    오류가 0이 될 때까지 수정을 반복하되, 최대 8번 시도하도록 상한선을 설정한다.

    /goal attendance.json 파일의 중복 출석 기록을 제거하고 bash validate_attendance.sh 를 실행했을 때 오류가 0이 될 때까지 반복해줘. 최대 8번 시도 후 멈추고, 해결 못한 오류가 있으면 목록을 보여줘
  3. 결과 확인 및 goal 종료

    goal이 달성되면 자동으로 멈춘다. 중간에 취소하려면 /goal clear를 입력한다.

    /goal       # 현재 goal 상태 확인
/goal clear # 진행 중인 goal 취소
/goal을 실행하면 Claude는 매 턴마다 validate_attendance.sh 결과를 확인하고, 오류가 남아 있으면 attendance.json을 수정한 뒤 다시 검증한다. 오류가 0이 되거나 최대 턴(8번)에 도달하면 멈추고 결과를 보고한다.
/goal은 파일을 직접 수정할 수 있다. 실행 전에 attendance.json을 백업해 두거나, 버전 관리(git) 하에서 실행하여 되돌릴 수 있도록 해야 한다.
● 고급 Power User 클라우드 루틴으로 NFC 학급 관리를 완전 자율화
P-1 고급 매일 아침 자동 출석 집계 보고서 — /schedule 클라우드 루틴
교감 C는 매일 아침 8시에 전교생 출석 현황 요약 보고서를 담임 교사들에게 이메일로 보내고 싶다. 개인 컴퓨터가 꺼져 있어도 자동으로 실행돼야 하므로 로컬 /loop 대신 /schedule 클라우드 루틴을 사용한다. 전제 조건: Gmail Connector가 /schedule에 연결되어 있고, classroom-nfc 저장소가 GitHub App과 연결되어 있어야 한다.
사용 요소
/schedule /loop vs /schedule 비교
단계별 실행
  1. GitHub 계정 연동 확인

    /schedule은 GitHub Actions와 연동해 실행하므로 /web-setup으로 사전 연결이 필요하다.

    /web-setup
  2. /schedule로 루틴 생성 시작

    어떤 작업을 언제 실행할지 자연어로 설명하면 Claude가 대화식으로 세부 설정을 안내한다.

    /schedule 매일 아침 8시에 classroom-nfc 저장소의 attendance/ 폴더에서 전날 출석 데이터를 읽고, 미출석 학생을 학급별로 집계해서 Gmail로 담임 교사 이메일 목록에 발송해줘
  3. 루틴 확인 및 관리

    생성된 루틴은 claude.ai/code/routines 에서 확인·수정·일시정지·삭제할 수 있다.

    /schedule   # 기존 루틴 목록 확인 및 관리
/schedule로 생성된 루틴은 Anthropic 클라우드 인프라에서 실행된다. 지정된 시각에 루틴이 시작되면, 연결된 Connectors(Gmail, GitHub 등)를 통해 데이터를 읽고 처리해 결과를 발송한다. 로컬 세션이나 컴퓨터 상태와 무관하게 동작한다.
처음에는 읽기 전용 작업(데이터 읽기, 보고서 생성)부터 시작하고, 안정성을 확인한 뒤 쓰기·발송 권한을 추가하는 것이 안전하다. /schedule 루틴은 운영 환경에 직접 영향을 미치므로 신중하게 설정해야 한다.
