1. /loop — 시간 기반 루프

Bundled Skill 세션이 열려 있는 동안 프롬프트를 반복 실행한다. Claude Code가 세션 안에서 직접 처리하므로 로컬 인터넷 연결과 활성 세션이 필요하다.

/loop [interval] [prompt] — 기본 문법

interval은 숫자+단위(예: 30s, 5m, 2h)로 지정한다. prompt는 매 실행 시 전달할 지시문이다. 둘 다 선택 사항이지만, 생략 조합에 따라 동작이 달라진다.

# interval + prompt: 5분마다 NFC 리더 상태 확인
/loop 5m NFC 리더의 연결 상태를 확인하고 이상이 있으면 오류 로그를 기록해줘

# interval만: 30초마다 .claude/loop.md 지침 실행
/loop 30s

# 둘 다 생략: 자기주도 페이싱으로 자율 유지보수
/loop

/loop 모드 비교

모드intervalprompt동작적합한 상황
인터벌+프롬프트지정지정고정 간격으로 지정 프롬프트 실행NFC 리더 폴링, CI 상태 확인
인터벌만지정생략고정 간격으로 .claude/loop.md 실행팀 공유 유지보수 루틴
자기주도생략지정ScheduleWakeup으로 스스로 간격 결정간격이 가변적인 작업 감시
완전 자율생략생략자기주도 + .claude/loop.md 지침자율 프로젝트 유지보수
인터벌을 너무 짧게 설정하면(예: 10초 이하) API 비용이 빠르게 쌓이고 속도 제한에 걸릴 수 있다. 실제 변경이 발생하는 주기에 맞춰 간격을 설정할 것.

💡 별칭: /proactive는 /loop의 별칭이다. 자율적으로 작업을 감시하는 에이전트라는 의미를 강조할 때 사용한다.

2. /goal — 목표 기반 루프

에이전트가 명시된 조건이 충족될 때까지 여러 턴에 걸쳐 스스로 작업하도록 한다. 조건은 계산 가능하고 검증 가능해야 한다. "충분히 좋을 때"처럼 주관적인 기준보다 "모든 테스트가 통과됐을 때", "파일 수가 0이 됐을 때"처럼 판단 기준이 명확한 조건에 적합하다.

/goal [condition] — 기본 문법

condition은 완료 상태를 기술하는 자연어 문장이다. 턴 제한을 함께 명시하면 무한 루프를 방지할 수 있다.

# NFC 출석 데이터 검증: 오류가 0이 될 때까지
/goal NFC 출석 데이터에서 중복 기록을 모두 제거하고 무결성 검사를 통과할 때까지, 최대 10번만 시도해줘

# 성능 목표: Lighthouse 점수가 90 이상이 될 때까지
/goal 홈페이지 Lighthouse 점수가 90 이상이 될 때까지, 5번 시도 후 중단해줘

/goal 중단 조건

중단 방법명령설명
목표 달성자동condition이 충족되면 에이전트가 스스로 멈춤
최대 턴 도달condition에 명시"최대 N번 시도"를 condition에 포함시켜 강제 종료
수동 취소/goal clear활성 goal을 즉시 취소. stop, off, reset, none, cancel도 동일
현재 상태 확인/goal (인자 없음)현재 또는 가장 최근 달성된 goal 표시
턴 제한을 명시하지 않으면 에이전트가 목표를 달성하지 못할 때 무기한 반복될 수 있다. 항상 "최대 N번 시도" 또는 "N분 안에"처럼 상한선을 포함할 것.

3. /schedule — 클라우드 루틴

Anthropic 관리 클라우드 인프라에서 실행되는 정기 루틴을 만든다. 로컬 컴퓨터가 꺼져 있어도 실행되며, claude.ai/code/routines에서 관리할 수 있다.

/schedule [description] — 기본 문법

description을 입력하면 Claude가 대화식으로 루틴 설정을 안내한다. 사용할 도구(Connectors), 실행 일정, API 키 연동 등을 설정한다.

# 매일 오전 8시 NFC 출석 집계 보고서 생성
/schedule 매일 아침 8시에 어제의 NFC 출석 데이터를 집계해서 담임 교사에게 요약 보고서를 보내줘

# 주중 매시간 GitHub PR 리뷰 확인
/schedule 주중 매시간 새 PR 리뷰 코멘트를 확인하고, 내 코드에 대한 요청 사항이 있으면 자동으로 수정해줘

/loop vs /schedule 비교

항목/loop/schedule
실행 환경로컬 세션Anthropic 클라우드
세션 필요 여부필요 (세션 닫히면 중단)불필요 (PC 꺼도 실행)
최소 간격제한 없음약 1시간 (루틴 정책)
도구 연동MCP 서버 기준Connectors (Gmail, GitHub 등)
적합한 용도개발 중 실시간 모니터링정기 보고·자율 운영

4. ScheduleWakeup — 자기주도 페이싱 내부 메커니즘

ScheduleWakeup은 /loop 자기주도 모드에서 Claude가 직접 호출하는 내부 도구다. 다음 실행까지의 대기 시간(delaySeconds)을 Claude가 스스로 결정하고 예약한다. 런타임은 60~3600초 범위로 고정한다.

캐시 TTL과 delaySeconds 설계 원칙

Anthropic 프롬프트 캐시의 TTL은 5분(300초)이다. 이 경계를 기준으로 웨이크업 간격을 설계해야 비용과 성능을 최적화할 수 있다.

대기 시간 범위캐시 상태권장 상황
60s – 270s캐시 유지 (warm)활성 모니터링 — NFC 리더 상태 확인, CI 폴링
정확히 300s캐시 미스 (최악)사용 금지 — 캐시 미스 비용을 치르면서 이점도 없음
300s – 1200s캐시 미스변화 주기가 긴 작업 — 배포 완료 대기, 장기 검증
1200s – 1800s캐시 미스유휴 루프 기본값 — 특별한 신호 없이 주기적 확인
300초(5분)는 캐시 미스를 치르면서 이점이 없는 최악의 선택이다. 이 값은 사용하지 말 것. 빠른 주기가 필요하면 270s 이하, 느린 주기가 필요하면 1200s 이상으로 설정한다.

5. .claude/loop.md — 자율 유지보수 지침

/loop를 인터벌·프롬프트 없이 실행하거나 /loop [interval]만 입력했을 때 Claude가 참조하는 지침 파일이다. 팀 공유 루틴 작업이나 프로젝트별 반복 점검 목록을 저장해 두는 데 유용하다.

기본 작성 형식

# .claude/loop.md — NFC 학급 관리 시스템 자율 유지보수 지침

매 실행 시 아래 순서로 점검한다:

1. NFC 리더 연결 상태를 확인한다 (GET /api/reader/status)
2. 지난 1시간 동안의 카드 인식 성공률을 계산한다
3. 성공률이 95% 미만이면 관리자에게 Slack 알림을 보낸다
4. 누락된 출석 기록이 있으면 재동기화를 시도한다
5. 이상이 없으면 "정상 운영 중" 로그를 남긴다
